## 二、缺陷分级

### P0 · 资金级漏洞：充值币可直接提现

**现象**：提现校验用的是 `users.credits`（唯一余额）：

```php
$need = $amount * $credits_per_yuan;      // 10 元 => 100 币
if ((int)$user->credits < $need) { ... }   // 只看余额
```

而充值加币也写同一个字段。结果：

```
充值 100 元 → 得 1000 币 → 申请提现 100 元 → 扣 1000 币 → 打款 100 元
净效果：白得 1000 币（只损失手续费百分比，默认 0%）
```

**影响**：可被用户循环套利，等价于站内无限提现。

**修复方案（推荐 A）**：拆分双账户
- `users.credits` 仅作**消费余额**（充值 + 分成入账，可消费，不可提现）
- 新增 `users.earnings` 作**可提现收益**（分成入账，提现只从这里扣）
- 或**方案 B（不改表，1 小时可上线）**：
  ```
  可提现额度 = min(credits, credits_total - 已提现金额 - 提现中金额)
  ```
  `credits_total` 已有（累计收益），仅需在执行提现时加封顶校验。

### P1 · 运营必需
1. **充值档位硬编码**：10/50/100 写死在视图里，不能改价、不能做「充 100 送 20」
2. **充值仅支付宝**：`createCreditsOrder(..., 'alipay')` 写死，微信/QQ 通道已配置却不用于充值
3. **财务页「站币」标签无筛选**：独立页 `/admin/credit` 有完整筛选，两套入口功能不一致
4. **无充值记录页（前台）**：订单表有数据，用户看不到自己的充值历史

### P2 · 体验缺失
5. 用户看不到充值记录（订单表有数据，前台无入口）
6. 用户看不到「我解锁过的图」
7. 作者看不到逐笔分成明细（只有累计 `credits_total`）
8. 充值成功页提示偏简（仅 toast 级文案）

### P3 · 运营分析
9. 无站币统计（今日充值 / 消费 / 分成 / 待提现）
10. 无销售排行（哪张图卖得好、哪个作者收益高）
11. 无解锁趋势
12. 无异常监控（单用户短时间大额充值+提现）
